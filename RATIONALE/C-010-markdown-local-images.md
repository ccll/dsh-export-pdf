# C-010 嵌入原图同时覆盖 Markdown 引用的本地图片

日期: 2026-11-17

#### 上下文

东家在 PDF 视图页把图片模式选成“嵌入原图”，导出结果里仍是 `[图片: 改前第 1 页]` 占位文字。定位到那一刻的会话：助手用 Markdown 语法写了 `![改前第 1 页](</tmp/dsh-sample/before-1.png>)`，两张截图都不是上传附件，而是消息正文直接引用的本地文件；用同一份会话日志复现，嵌入与占位两份 PDF 同字节、位图数为 0。

C-006 把嵌入范围限定在会话附件库，C-008 让 Markdown 图片只呈现占位文字。两条都没有覆盖“消息正文引用本地图片”的情形，但聊天界面经宿主文件路由 `/api/file` 能把这类图片显示出来——同一条消息在聊天里看得见图，在 PDF 里只剩文字，用户无法接受。

#### 决策

“嵌入原图”同时嵌入上传的附件图片与消息正文里 Markdown 引用的本地图片。本地图片经宿主文件服务 `ctx.fs` 读取，路径解析、权限与沙箱策略和聊天界面显示本地图片同源；只接受常见图片扩展名且字节嗅探为真图片，读取上限沿用宿主附件图片准入上限。http、https 远程地址仍不抓取；读取失败、格式不支持或超出上限时回退 `[图片: alt]` 占位。占位与不导出模式保持文本占位。

#### 被否方案及原因

- **保持只嵌入附件，改文案说明范围**：不需要改宿主装配，但东家要的是“聊天里看得见的图，PDF 里也看得见”；改文案不解决导出内容缺失。
- **在插件里直接用 Node `fs` 读路径**：绕过宿主文件服务的沙箱与权限策略，等于在插件里另开一条不受控的本地读取通道；沙箱模式下会出现 GUI 显示图片而导出拒绝读取的割裂。
- **抓取 http、https 图片地址**：会话内容不可信，抓远程地址会把导出变成外联请求，并泄露导出时机与网络位置。
- **只按扩展名信任、不校验字节**：把非图片内容编码成 `data:` 会破坏 PDF 渲染，也让任意文件有机会进入产物。
- **把工具结果里的图片也一并导出**：那是另一类内容（工具结果不是消息正文），范围更大，与本次“同一条消息在聊天与 PDF 里一致”的目标无关。
