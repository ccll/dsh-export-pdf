# C-007 窄视口用新标签页打开完整 PDF 而非页内 PDF.js

日期: 2026-11-17

#### 上下文

桌面浏览器在 iframe 内用原生 PDF 查看器可以滚动全部页面；手机浏览器把同一份多页 PDF 装进 iframe 后，内置查看器只渲染第 1 页，iframe 内滚动与 `#page=` 片段都无法可靠翻页。PDF 文件本身仍是多页，问题在移动端的页内承载方式。东家要求手机也能访问全部页面，并在方案选择中拍板“新标签页打开完整 PDF”。

#### 决策

视口宽度不超过 720px 时，PDF 页不渲染 iframe，改为显示提示与“打开完整 PDF”链接；链接在新标签页打开与预览/下载相同的同源 PDF URL，由系统 PDF 查看器承担多页浏览。桌面视口保持原生 iframe 页内预览；两种入口共用同一份导出结果、文件名、选择与图片模式。

#### 被否方案及原因

- **页内 PDF.js 渲染**: 能在手机页内逐页显示，但需要引入 `pdfjs-dist`、worker 与宿主静态资源/新预览路由，客户端包体和维护面显著增大；当前诉求用系统查看器即可满足，不为单一平台限制引入重型依赖。
- **保留受限 iframe**: 改动最小，但手机用户无法访问第 1 页之后的内容，直接违反“可浏览全部页面”的诉求。
- **新增页码按钮 + iframe 片段**: 依赖手机内置查看器支持片段翻页；实测 iframe 内片段不能可靠改变页面，失败时仍是同样的不可用。
- **手机端自动重定向到 PDF URL**: 不需要额外点击，但会离开会话页且可能被浏览器拦截为意外导航；显式链接更可控。
