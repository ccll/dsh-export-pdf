# C-005 默认最简导出并用复选框按需加入内容

日期: 2026-11-16

#### 上下文

原 PDF 固定包含用户消息、助手回复与单行工具调用摘要，图片与附件以占位符出现。东家在验收后提出：有时需要一份只含双方消息本体的干净 PDF，用于分享或归档；希望选择能同时作用于预览与下载，并在预览页标题栏直接操作。

#### 决策

默认导出只保留用户消息与助手回复的文本；标题栏用两个独立复选框按需加入“工具调用摘要”和“附件占位”。选择变化同时驱动预览与下载，附加选择对应的下载文件名加后缀；新会话回到默认最简，不跨会话记忆。没有文本的纯附件消息在未选附件占位时不进入 PDF。

#### 被否方案及原因

- 默认完整、把“仅消息”作为一次性开关：默认导出仍夹带执行细节，分享前必须记得切换；东家明确要求默认最简。
- 二选一分段开关“完整/仅消息”：只能表达全有或全无，未来增加思考过程或工具输出时要重做控件；复选框可逐项扩展。
- 只在下载时弹格式菜单：预览与下载可能不一致，用户无法先确认干净版的样子，违背“所见即所得”。
- 附件占位固定保留：纯附件消息仍会出现占位行，不符合“只含消息本体”的默认承诺。
- 跨会话记住上次选择：分享场景下会悄悄沿用上次的详尽选择，行为不可预测。
