# C-006 图片独立三态：不导出、占位或嵌入原图

日期: 2026-11-17

#### 上下文

C-005 让 PDF 默认只保留消息文本，图片与文件都作为附件占位，且共用一个“附件占位”复选框。东家在验收图片内容后提出：图片应当能选择嵌入原图，而不只是占位；占位复选框同时控制图片与文件，无法表达“图片嵌入、文件仅占位”。东家选择独立三态图片选择、默认占位，并要求实现前先确认口径。

#### 决策

图片改为独立的三态选择：不导出、占位、嵌入原图，缺省占位。文件附件改由独立复选框控制，始终以 `[附件: 文件名]` 占位，不嵌入文件本体。占位模式在原位置显示 `[图片]` 并保留纯图片消息；嵌入模式从会话附件库读取消息引用的原图，按版心缩放嵌入并保持图文顺序，读取失败、格式不支持或附件缺失时回退为 `[图片]`；不导出模式省略图片与纯图片消息。图片模式进入 URL、缓存键与文件名：嵌入追加 `-images`，不导出追加 `-no-images`，占位保持默认文件名。

#### 被否方案及原因

- 在“附件占位”复选框中加图片模式下拉：文件与图片仍耦合，无法表达图片嵌入而文件仅占位；东家明确选择独立控件。
- 二元“占位/嵌入原图”开关：缺少“不导出”状态，无法恢复完全干净的纯文本 PDF，也不适合对图片敏感的场景。
- 默认嵌入原图：PDF 体积和敏感内容风险在默认路径上放大；东家确认默认占位。
- 把文件也嵌入 PDF：任意文件没有统一的 PDF 内嵌呈现方式，强行转换会引入格式支持与损坏风险，超出本次范围。
- 只读取 `imageHostPath` 直接引用宿主文件：会把宿主路径暴露给渲染层并绕过附件校验；应经 `ctx.attachments.readImage` 校验引用和字节。
