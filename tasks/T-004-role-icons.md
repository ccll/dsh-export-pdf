# T-004 角色图标

状态: active
类型: UI/UX 改进
风险等级: minor
风险面: 无（仅 PDF 版式呈现）
决策依据: 东家 2026-11-16 在 Tailscale 验收右对齐版式后要求“对话框旁边”加两个小图标，用小人代表用户、机器人代表 agent；PRD 新增 R-01-010 与 M-005 承接。

## 背景与目标

- 背景: 用户消息已右对齐、助手回复左对齐，但角色仍只靠“用户/助手”文字区分；东家希望在消息旁加人形与机器人图标，进一步贴近 DSH 会话窗口的直觉。
- 目标: 用户角色标签外侧显示人形图标，助手角色标签外侧显示机器人图标；图标为内联 SVG，不依赖网络、字体或位图资源，不改变消息宽度与分页。
- 非目标: 不改转录内容与顺序、不改路由/缓存/鉴权、不引入外部图标库或前端依赖、不改气泡配色。

## 差距评估

- 现状: `src/render.mjs` 的角色标签只有“用户”“助手”文字，没有图形标识。
- 差距: 缺少 R-01-010 的两条 AC 与测试锚点。
- 影响面: 仅 `src/render.mjs` 的角色标签结构与少量样式；PDF 文本层、页数与消息边界不变。

## 收敛方案

- 角色标签内嵌 16×16 内联 SVG：人形（圆头 + 肩部）用 `currentColor` 继承用户标签的蓝色；机器人（方头 + 天线 + 白点眼睛）继承助手标签的灰色。
- 用户图标放在“用户”文字右侧并随标签靠右；助手图标放在“助手”文字左侧并随标签靠左；图标 `aria-hidden`，角色文字仍保留在 PDF 文本层。
- 图标尺寸约 3.4 mm，放在角色行内，不进入消息正文；`break-after: avoid` 继续保证角色行与正文同页起排。
- 无分叉点: 东家已指定图标语义与“旁边”位置，SVG 形状与颜色深浅属实现自由。

## 测试计划

- `test/render.test.mjs` 断言用户条目含 `data-role-icon="user"`、助手条目含 `data-role-icon="assistant"`，且每个条目各一个图标、无外部 `http` 图片引用。
- 真实 Chrome PDF 用例继续跑 A4、分页、右对齐与词框边界；另用 `pdftoppm` 生成第一页 PNG 目视核对图标位置与打印清晰度。
- 目标 AC: R-01-010/AC-01、R-01-010/AC-02。
